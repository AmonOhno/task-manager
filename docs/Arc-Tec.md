# 使用技術方針（AI駆動開発を前提）

## 6-0. 基本思想

本プロダクトは以下を前提とする。

- **人が考えるのは「判断」だけ**
- 記述・整理・要約・分解はAIに委譲する
- UI / データモデル / AI を疎結合に保つ

AIは「補助機能」ではなく、**設計思想の一部**として扱う。

---

## 6-1. フロントエンド

- **TypeScript**
- **React**（関数コンポーネント前提）
- **状態管理**：Zustand  
  - 軽量
  - UI主導設計との相性が良い
- **UI**：shadcn/ui + Tailwind CSS
- **日付操作**：dayjs

### フロントエンドの責務

- TODO一覧の表示ロジック
  - 優先度算出
  - キャパシティフィルタ
- 一時的な判断状態の保持
  - 今日はやらない
  - 翌日送り など
- AI生成結果のレビュー／採用判断

---

## 6-2. バックエンド

- **Node.js（TypeScript）**
- **API**：REST  
  - 将来的に GraphQL 化の余地あり
- **認証**：将来対応  
  - 初期は単一ユーザー想定

### バックエンドの責務

- 正規化されたタスクデータの永続化
- 状態遷移の整合性保証
- AI生成結果の保存
  - draft（下書き）
  - adopted（採用済み）の区別

---

## 6-3. データベース

- **PostgreSQL**

### 採用理由

- Task の自己参照による階層構造
- 状態履歴の管理
- 将来的な分析用途
  - 工数
  - 業務傾向
  - ボトルネック分析

---

## 6-4. AI活用ポイント（最重要）

### 対象領域

1. 問合せ内容からのタスク分解  
   - 背景文 → プロジェクト／タスク／サブタスク案生成
2. 背景・概要文の要約
3. 回答文・提出物文面の下書き生成
4. 状態遷移候補の提示  
   - 例：レビュー完了 → 提出可能

### AIの立ち位置

- **常に draft（下書き）扱い**
- AIが自動で確定させることはしない
- 人が「採用」して初めて正となる

---

## 6-5. AI連携設計方針

- AIは**独立サービス**として扱う
- 入出力は必ず構造化（JSON）
- プロンプトはコード管理する  
  - 属人化防止
  - 再現性確保

### 入出力例

```json
{
  "input_type": "inquiry_text",
  "output": {
    "project": "string",
    "tasks": [
      {
        "title": "string",
        "subtasks": ["string"]
      }
    ]
  }
}
